# 实施路线图

路线图遵循课程要求的实现顺序。每个阶段完成后，应在 `progress.md` 中记录负责人、提交和验证证据。

| 阶段 | 内容 | 最低验收证据 | 状态 |
| --- | --- | --- | --- |
| M0 | 仓库、工具链、文档和 CI | 容器环境自检通过 | 已完成 |
| M1 | Boot Sector | BIOS 启动后显示小组自定义信息 | 未开始 |
| M2 | 保护模式与 Loader | 切换到保护模式并正确加载内核 | 未开始 |
| M3 | 内核与中断 | 内核入口、GDT/IDT、时钟和键盘中断可验证 | 未开始 |
| M4 | 进程管理 | 单进程运行、多进程调度和进程创建可演示 | 未开始 |
| M5 | 输入输出 | TTY、控制台和键盘输入形成稳定交互 | 未开始 |
| M6 | 文件系统与系统调用 | 基础文件操作及 `fork/exec/wait` 可验证 | 未开始 |
| M7 | Shell 与命令扩展 | `help`、`clear`、`cat`、`stat`、`rm` 可运行 | 未开始 |
| M8 | 进阶与交付 | 可选 `ps`、回归测试、截图、报告和答辩材料 | 未开始 |

## 阶段规则

- 每个里程碑在合并前至少包含构建步骤、运行步骤和验收结果。
- 参考实现用于理解和对照；复制或改写代码时必须在提交和参考资料文档中说明来源。
- 先保持启动链路可运行，再扩展下一个模块，避免多个未验证模块同时堆积。
- 功能演示之外，还应保存失败场景、调试过程和修复依据，供项目报告使用。
